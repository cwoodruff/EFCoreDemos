// * Takeaway *
//
//   EF.Constant is 4-6x slower when the list keeps changing. The
//   rows come back just as fast - the time is SQL Server compiling
//   a brand-new plan for every distinct IN (1, 2, 3, ...) text, and
//   each of those plans then sits in the cache, used once.
//
//   The EF 10 default (one parameter per value, padded to buckets)
//   is the safe middle: a handful of reusable plans, and SQL Server
//   still sees the real values when it builds each one.
//
//   EF.Parameter (one OPENJSON parameter) wins on big lists: one plan
//   for every size and only one parameter to send. The catch is that
//   the optimizer can't see inside the JSON, so it guesses the row
//   count - fine on a primary key, worth checking on skewed columns.
//
//   Keep the default. Reach for EF.Parameter on large lists, and for
//   EF.Constant only when a list is genuinely fixed (a few status codes).
