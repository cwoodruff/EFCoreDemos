// * Takeaway *
//
//   "Stored procedures are faster" - not here. The sproc path is ~20%
//   SLOWER, with noisier timings, and allocates about the same.
//
//   SQL Server caches plans for parameterized ad-hoc SQL just like it
//   does for procedures, so the old precompiled-sproc advantage is gone.
//   The EXEC adds a little server-side overhead on a trivial query.
//
//   Tracking vs NoTracking moves the needle more (~30% time, 2.3x memory)
//   than LINQ vs sproc does. Use sprocs for security boundaries or
//   logic that belongs in the database - not for speed.
