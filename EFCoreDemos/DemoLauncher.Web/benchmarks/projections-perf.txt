// * Takeaway *
//
//   Chinook.Track is narrow (~9 columns). Projection still saves you the
//   tracker overhead and a few unused fields, but the dramatic 5-20x gap
//   the talk mentions only shows up on wide tables (think: Books with
//   Synopsis nvarchar(max), or any audit-heavy entity with 50 columns).
//
//   Look at the GENERATED SQL instead - that is the lasting reason to
//   project. Open ./sql/full-hydration.sql vs ./sql/anon-projection.sql
//   side by side: one pulls every column, the other pulls three.
//
//   Rule of thumb: project to DTOs on every read endpoint. The wins
//   compound the wider your real table gets.
