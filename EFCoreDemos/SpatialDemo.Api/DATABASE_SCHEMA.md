# Database Schema

Database `spatialdemo` on the docker SQL Server (`localhost,1433`). The schema is created by the EF Core migration `Migrations/20261008182259_InitialCreate.cs`, which `Program.cs` applies on startup.

## Locations

```sql
CREATE TABLE [Locations] (
    [Id] int IDENTITY(1,1) NOT NULL,
    [Name] nvarchar(200) NOT NULL,
    [Coordinates] geography NOT NULL,
    CONSTRAINT [PK_Locations] PRIMARY KEY ([Id])
);
```

Maps to `SpatialDemo.Api.Entities.Location`; `Coordinates` is a NetTopologySuite `Point`.

## CityBoundaries

```sql
CREATE TABLE [CityBoundaries] (
    [Id] int IDENTITY(1,1) NOT NULL,
    [CityName] nvarchar(200) NOT NULL,
    [Area] geography NOT NULL,
    CONSTRAINT [PK_CityBoundaries] PRIMARY KEY ([Id])
);
```

Maps to `SpatialDemo.Api.Entities.CityBoundary`; `Area` is a NetTopologySuite `Polygon`.

## Spatial Conventions

- SRID 4326 (WGS84); X = longitude, Y = latitude
- Distances on `geography` are in meters
- Polygon rings must be closed and valid (no self-intersections)

## Seed Data

Seeded by `Program.cs` when `Locations` is empty:

- Locations: Times Square, Central Park, Empire State Building
- CityBoundaries: "New York", a simple rectangle (-74.02..-73.93 lon, 40.70..40.83 lat)

## Indexes

Only the primary keys exist. EF Core does not create spatial indexes (it has no fluent API for them), and the migration contains none. For larger data sets, add them in a migration with `migrationBuilder.Sql(...)`:

```sql
CREATE SPATIAL INDEX [IX_Locations_Coordinates] ON [Locations] ([Coordinates]);
CREATE SPATIAL INDEX [IX_CityBoundaries_Area] ON [CityBoundaries] ([Area]);
```

## Queries Generated by the Endpoints

- `/locations/near`: `WHERE [l].[Coordinates].STDistance(@origin) <= @radiusMeters`
- `/cities/{cityName}/locations`: `WHERE @area.STContains([l].[Coordinates]) = CAST(1 AS bit)`
